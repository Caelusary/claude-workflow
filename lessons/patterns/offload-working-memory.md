---
title: "Give users a place to park intermediate results"
status: open
kind: quality
dimension: ui-planning
seen: 1
---
**Principle:** When a task chains several steps or calculations, the app gives the user somewhere to keep intermediate results (scratch pad, history, running tally) that stays reachable without covering the problem.
**Why it recurs:** Designers model the task as input and output and forget the human holding numbers in their head between steps.
**Check:** How many values must the user remember between steps? If more than two, where can they put them, and can they still see the problem while doing so?
